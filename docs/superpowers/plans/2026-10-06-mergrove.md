# Mergrove Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an original, production-quality 5 × 5 cascade merging game with original SVG sprites, deterministic rules, responsive accessible controls and shared guest/account persistence.

**Architecture:** Keep all merge rules and RNG in a pure TypeScript engine. React owns interaction/rendering only, with an in-document SVG symbol sprite bank and a game-scoped stylesheet. Durable state uses the existing `useGameSave` abstraction; no direct Firebase or new dependency is introduced.

**Tech Stack:** Existing React 19 + TypeScript + Vite + Vitest + Playwright + shared Firebase save platform.

**Spec:** `docs/specs/2026-10-06-mergrove-design.md`

## Global Constraints

- Work only on the moving shared `main`; refresh the live ref before every mutation and preserve parallel-agent changes.
- No new runtime dependency, server, external runtime art/font/API, privileged credential or direct game Firebase call.
- Native-button interaction must remain usable at 320 CSS px, 200% text, touch, pointer and keyboard, with reduced motion honored.
- Every game-local source/test/index integration updates both Mergrove spec and tracker in the same commit.
- Do not mark verified until exact CI + Pages evidence exists.

## Review Focus

- Chain resolution after a merge creates another same-tier component at the anchor.
- Full board must remain recoverable when sunlight can pay for Compost.
- Saved `gameOver` must agree with board occupancy and sunlight rather than trusting serialized flags.
- Disabled occupied cells must remain visually legible even though they are not placement targets.
- Parallel-agent catalog/index/task changes must survive integration unchanged.
